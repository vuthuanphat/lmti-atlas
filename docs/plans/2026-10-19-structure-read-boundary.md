# Structure v3 read boundary and trusted integration v2

Date: 2026-10-19. Applied source build under STRUCT-01. This is not a new
packaged hierarchy release, migration implementation or completed MVP claim.

`structure-snapshot` is a fixed native read command. It derives a scoped v3 DTO
from one validated native document and a storage-private shared serializer.
Project/subsystem/site/area/physical-parent/environment privacy is inherited
before endpoint selection. Unknown and denied selected sites return the same
empty physical view, while permitted project-wide logical references remain.
Flat v1 stores can explicitly return `structureDeclared: false`; no migration,
synthetic site, placement or role is inferred. Legacy snapshot/proposal paths
remain closed for structured stores until their own policy is implemented.

Python validates exact v3 shapes, references, classifications, cycles and depth.
Structure is a fixed source capability and part of cursor policy. Normal task
context adds ancestors without descending from those ancestors into siblings;
an explicit container query can descend within its budget. Environment is a
separate membership, not an undirected shortcut. Native snapshots fail wholly
above 4 MiB; normal Agent response and traversal bounds continue to apply.

The trusted integration v2 file has exactly the six v1 fields plus JSON boolean
`structure: true`; v1 cannot carry the field and v2 false/number/null values are
invalid. The native generator and protected client-config owner retain the same
sixteen argv values and whole-file SHA-256 pin. Python pins/parses once before
constructing the native capability. Generic injected sources must already match
that capability. Integrated MCP expands kind/relation enums per instance, with
five tools and the unchanged response envelope; default MCP retains four tools.

The web query vocabulary supports subsystem/site/area/environment and the five
declared hierarchy relation types. These filters narrow a trusted grant; they do
not enable structure. The internal broker request now requires integrationSha256
(null exactly when integrationConfig is null). Its value comes from the launch
pin, never browser arguments. The child verifies it before source construction.
This closes an A-to-B-to-A substitution window left by parent-only before/after
checks. On child failure the parent also rechecks/latches the source, preserving
CONFIG_CHANGED and permanent revocation without retrying reads or writes.
