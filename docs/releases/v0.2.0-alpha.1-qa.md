## Protection and distribution

SQLite is unencrypted and nonsecret-only. DPAPI protects specific client
backups/journals and writer coordination, not the domain databases. There is no
OS sandbox or multi-user authorization service. No shell/SQL/path HTTP tool,
Agent write permission, device command or silent migration was added.
Source folders/databases survive library reference removal. New bindings require
relaunch; library management never expands a running session's project access.

Keep `.gitignore` configured before every push. Operational `.lmti/`, credentials,
databases and session material are excluded. Secret scans must review any new
finding privately; existing synthetic sentinels are not grounds to suppress rules.
Qt Core/Sql notices and corresponding source remain required. Manifest checksums
are integrity evidence, not a publisher signature. Node/Python remain external
trusted prerequisites. The browser runtime contains fixed owner bundles, not the
unrestricted source CLI.

## PowerShell UTF-8 follow-up

An actual Windows PowerShell 5 startup smoke exposed console-code-page corruption
of Unicode launch JSON. Launcher/catalog and doctor input now use a dedicated
UTF-8 writer without BOM, and owner output/error readers use explicit UTF-8.
The same synthetic payload failed the default writer byte comparison and passed
the UTF-8 writer. A regression executes the actual private launcher/doctor helper
ASTs with Windows PowerShell 5 and verifies exact input bytes and Unicode output.
Actual packaged startup also accepts a reviewed Vietnamese grant and Unicode
data/source folders. This grants no anonymous browser session.

The first two hosted native attempts for the earlier core commit failed the same
hierarchy-refusal probe despite full local passes and five separate repetitions.
The original bounded log did not expose its assertion payload, so its cause is
not established. The harness now suppresses noninteractive module progress only
and emits bounded failure metadata (case/status/error category/byte counts), with
no arguments, raw stderr, locators or session material. Exact refusal/empty-stdout
assertions and all production guards/timeouts remain unchanged. Later results do
not erase these failed attempts; see the PR checks and delivery verification record.
