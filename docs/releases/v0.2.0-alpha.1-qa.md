## Hosted-CI repair history

The first launch CI run found permissive `.lmti` directories in two CLI test
fixtures under the runner's default POSIX umask. Those fixtures now create the
directory with mode `0700`; production permission checks and test assertions
were preserved. The two affected suites passed all 15 tests on Windows after
the fix; hosted Linux results are recorded separately in the PR checks.

The first Windows build could not find the script's Visual Studio 2022
generator on `windows-latest`. The workflow now selects `windows-2022`, whose
[documented toolchain](https://github.com/actions/runner-images/blob/main/images/windows/Windows2022-Readme.md)
includes Visual Studio 2022. These failed runs remain visible; later green runs
do not erase their history.

The Windows package verifier also exposed failures in system-temporary asset
and broker fixtures. A local reproduction using a Windows 8.3 TEMP alias
failed all seven asset tests; a canonical temporary directory passed six and
skipped the file-symlink case. CI and the verifier now select isolated canonical
temporary directories. Production alias/junction guards, positive fixture
controls and rejection assertions were not relaxed. TAP is selected explicitly
to report bounded failure names without logging assertion payloads.

Further Windows CI reached the TypeScript suites and exposed an inherited-DACL
normalization difference in the native audit helper. When an empty target already
has exactly the source's complete Access SDDL, the helper now leaves it intact
instead of asking Windows to recompute inheritance. It still checks the complete
descriptor, source/target identities, empty target and canonical paths before
returning success. Differing descriptors still require a successful copy and
exact verification; existing denial and protected-DACL tests remain enabled.
The native synthetic checks and all 116 affected local TypeScript tests passed
(one POSIX-only case skipped). Hosted results remain in the PR checks.

A small Windows audit/freshness job now runs before the full native build.
Freshness race fixtures use their canonical temporary root and assert that the
mutation was actually injected. Numeric native failure locations are visible
only in synthetic test output; the helper IPC still emits no diagnostic payload.
The revised helper must be rebuilt into release artifacts and reverified;
the earlier 97-file byte-equivalence result does not apply to that new helper.

The full Windows run then reproduced an inventory race whose directory
timestamps did not change. Freshness checks now compare directory entries at
the end of each bounded traversal as well as metadata. The regression injects
an addition while holding the directory stat constant; no delay or relaxed
assertion is used. This compiler change also requires rebuilding the packaged
owner bundles and repeating the package verifier.

After Windows TypeScript reached 664 pass/5 skip and 37 of 39 native targets
passed, two MCP desktop targets exposed CMake selecting `python3.exe`. The
[official Windows Python toolcache installer](https://github.com/actions/python-versions/blob/main/installers/win-setup-template.ps1)
creates that filename as a symlink. Build configuration now explicitly selects
the real Python executable and rejects linked runtime paths. The product's
symlink guard remains unchanged. Native/Python CI results after this adjustment
must be checked separately; earlier partial runs are not a full pass.

## Security and distribution review

- The baseline dependency audit reported no advisories. Vitest was updated to
  4.1.12; no security guarantee is inferred from an audit result.
- Gitleaks 8.30.1 found four current-source and six reachable-history matches,
  all reviewed synthetic unit-test sentinels. No rule suppression was added.
  The prepared runtime package had zero detections. This does not certify
  absence of every possible secret or inspect text embedded in images.
- Only synthetic project data appears in the launch screenshots.
- Operational `.lmti/`, databases, credentials and session material are excluded
  from the public source and runtime distribution. Check `.gitignore` before
  every push.
- Apache-2.0 source, third-party notices, build dependency inventory and the
  corresponding Qt 6.12.0 source are prepared. Runtime checksums are integrity
  records; the Windows package has no publisher signature.
- GitHub Private Vulnerability Reporting was enabled and verified on 2026-10-23.
