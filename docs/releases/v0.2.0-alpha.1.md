# LMTI v0.2.0-alpha.1

Status: local release candidate; not published. This alpha extends the original
project-memory CLI with a React + Vite local browser workspace, native project owners and
scoped Agent integration. Supported distribution target: Windows x64.

## Changes since v0.1.0-alpha.1

- Local React workspace over a loopback-only authenticated API; English and
  Vietnamese presentation, project selection and session lifecycle handling.
- Typed C++/SQLite topology, project/library, logical/physical hierarchy and
  desired-configuration owners; Qt desktop remains available as a fallback.
- Project MCP profiles with client configuration preview, apply and restore;
  Python SDK/MCP reads and reviewed proposals retain owner and scope checks.
- Evidence-bearing context from declared structure, reviewed code/document
  summaries and eligible memory. Controlled replay is labeled separately from
  live observations.
- Project copy, library activation and recovery workflows with revision checks,
  bounded grants and explicit review of write operations.
- Memory/storage/migration boundary hardening and inter-process audit coordination;
  Windows audit DACL preservation uses a narrow native helper.
- Smaller delivery artwork and paused hidden presentation clocks; bounded
  process admission and reduced repeated metadata reads.
- CLI dispatch split into maintainable commands; Go remains a compatibility path.
- Go credential scanning is under `internal/credentialscan`; protected secrets
  directories remain blocked, without a source-only exception for the old path.
- Canonical repository metadata, aligned release versions and hardened CI setup.
- Vitest 4.1.12 fixes the dev-tool advisories
  [GHSA-qxg6-89mg-rqv8](https://github.com/advisories/GHSA-qxg6-89mg-rqv8) and
  [GHSA-xp26-3454-mjgp](https://github.com/advisories/GHSA-xp26-3454-mjgp).

| Surface | Version |
| --- | --- |
| GitHub candidate / JS workspaces / MCP server identity | `0.2.0-alpha.1` |
| Python project metadata (PEP 440) | `0.2.0a1` |
| CMake project numeric version | `0.2.0` |

Release versions do not change AMF, privacy-policy or database schema identifiers.
Inspect the existing store version through its owner; do not infer migration
requirements from the product version. Namespace `@atlas/*` remains internal.
CLI callers must use supported flags: for project memory classification use
`--privacy-level`, rather than an unrecognized `--privacy` flag. Unknown flags
are rejected instead of being silently ignored.

## Run and build

See the [README](../../README.md), [local web guide](../local-web.md) and
[release build instructions](../release-build.md). Node 24+, Python 3.11+ x64
and the compatible Microsoft C++ runtime are prerequisites for the Windows ZIP.
Qt libraries and Python source are included; Node/Python are external prerequisites.
Use the launcher/API; opening `index.html` directly does not start LMTI.

## Known limitations

- Public alpha contracts can change. npm/PyPI installation is not a verified
  release channel for this candidate.
- Actual Cursor/provider OAuth, Google consent, an independent operator and a
  fresh Windows installation remain separate acceptance gates unless the local
  acceptance report explicitly records their completion.
- Linux checks exercise selected components; they do not certify full Studio
  support on Linux or macOS.
- Controlled replay is not a live IoT adapter. Device execution, multi-user
  authorization and encrypted topology storage are outside this alpha scope.
- Same-user filesystem races, network-filesystem locking and hardware power-loss
  guarantees are limited. Do not expose the loopback API over LAN or tunnels.
- Audit still processes the full ledger. Small synthetic benchmark results are
  not a throughput or latency guarantee for large operational logs.
- The Windows ACL helper rejects unsupported network/device paths and fails
  closed when permission preservation cannot be verified.

## Upgrade and rollback

1. Stop writers, API and Agents for the affected project.
2. Preserve the previous package and use each owner's backup procedure for
   project/library, memory and audit stores. Keep ledger/archive/lock files.
3. Verify the new ZIP checksum, extract to a new directory and run package doctor.
4. Test on a disposable copy first. Use the native owner's explicit preview and
   reviewed upgrade/copy workflow; do not import legacy memory implicitly.
5. Start the new package using an explicit data directory and restricted scope.

To roll back, stop all writers again and check schema compatibility before
starting the previous binary. A binary downgrade does not undo data operations,
retention or events. Do not mix pre-mutex and current audit writers. Preserve
evidence and restore only through a verified owner-compatible backup procedure.

## Release gates

The local acceptance report records actual pass/fail/skip counts and artifact
hashes. Hosted CI and clean-VM acceptance must not be inferred from local tests.
Before future publication: confirm the private security-reporting channel,
complete platform acceptance, review third-party source/license materials,
check `.gitignore` and tracked files, and run `lmti publish preflight`.
